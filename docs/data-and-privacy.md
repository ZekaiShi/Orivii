# 04 · 数据、备份与迁移

[教程目录](README.md) · 上一篇：[多个 Orivii 与解锁](identities.md) · 下一篇：[常见问题与排错](troubleshooting.md)

## 数据放在哪里？

打开 **更多 → 设置 → 存储与迁移**，可以查看当前角色的工作空间路径。

| 内容 | 保存位置或处理方式 |
| --- | --- |
| 角色聊天、记忆、偏好 | 工作空间内的 `.dot-memory`，沿用创建时选择的加密或明文方式 |
| 新建的其他角色 | 初始工作空间内的 `.orivii-profiles`，每个角色有独立资料目录 |
| 角色列表 | DSH 本地配置中保存名字、路径与验证策略；不包含聊天、密码或解密密钥 |
| 解锁状态 | 当前 DSH 后端进程的内存，退出或锁定后清除 |
| 本轮模型上下文 | 发送给你配置的模型服务进行处理 |
| 联网查询 | 必要查询词交给 DSH 的联网服务及相关网站 |

**本地保存不等于完全离线。** 你选择的模型、DSH 和其他插件各自有数据处理策略。加密保护磁盘上的资料，不能保护已被他人控制的操作系统或已经解锁的会话。

## 做一次可恢复的备份

1. 记下当前角色的工作空间，以及其他角色所在目录。
2. 锁定或退出所有正在使用这些资料的 DSH 后端，避免复制时文件仍在变化。
3. 复制整个工作空间到你控制的备份位置，确认包含隐藏目录 **`.dot-memory`**；有多个角色时还要包含 **`.orivii-profiles`**。
4. 另行妥善保管解锁密码。备份文件本身不会帮你找回密码。

默认目录结构大致如下，名称只作示例：

```text
你的工作空间/
├── .dot-memory/              第一个角色的资料
└── .orivii-profiles/
    ├── <角色目录一>/
    │   └── .dot-memory/
    └── <角色目录二>/
        └── .dot-memory/
```

你单独打开过的其他工作空间可能在不同位置，也需要分别备份。不要上传整个工作空间到公开 Git 仓库或 Issue，即使它已经加密。

## 升级插件

先备份，再按安装时使用的渠道更新。更新后重启 DSH，选择原来的工作空间解锁即可；插件代码和聊天资料是两部分。

从旧的 GitHub 安装包切换到 npm 包时：

1. 完成上面的资料备份。
2. 在 DSH 插件管理中停用旧 Orivii，避免两份同时启用。
3. 安装 **`dsh-orivii@1.0.1`**，按提示重启。
4. 选择原来的工作空间并解锁，核对聊天和角色是否完整。

旧 Release 的安装包文件名含 `dsh-companion`，不代表应该在 npm 上安装同名包。Orivii 的 npm 名字始终以本项目主页说明为准，目前是 **`dsh-orivii`**。

## 恢复与换电脑

在新电脑安装 DSH、配置模型并安装 Orivii。把备份恢复到你希望保存资料的位置，然后在 Orivii 的工作空间入口选择**含有 `.dot-memory` 的上一级目录**，输入原密码。

例如旧目录是 `D:\Orivii\.dot-memory`，应选择 `D:\Orivii`，不要直接选内部的 `.dot-memory`。

角色列表属于 DSH 的本地配置，新环境可能不会立即列出所有旧角色。通过工作空间入口逐个打开已有角色目录并解锁；不要为了补回列表而在旧目录里重建同名角色。没有检测到记忆库时，先核对路径与隐藏目录是否复制完整。

1.0.1 不提供自动跨设备同步，也不应让两个后端同时写入同一个同步盘目录。

## 导入更早的 Dot 聊天

**设置 → 存储与迁移 → 导入旧版 Dot 聊天** 会尝试读取当前浏览器可用的旧版聊天索引，只导入聊天气泡，原 DSH 记录保留。没有旧索引时，这个入口不能替代磁盘备份恢复。

## 哪些数据会进入问题反馈？

插件没有自动上传聊天的反馈服务。提交 Issue 时只提供必要、脱敏的错误和复现步骤。不要附带完整日志、个人目录、密码、密钥、聊天原文或记忆库。

发现安全问题请使用 [安全反馈说明](../SECURITY.md) 中的渠道。
